# 一、数据库分类
1. 数据库分位**关系型数据库**和**非关系型数据库**
2. 关系型数据库是指用关系模型（二维表格）来组织数据的数据库；非关系型数据库NOSQL是一种数据结构化存储方法的集合，可以是文档或者键值对
3. 非关系型数据库读写性能高，易于扩展，可以分为**内存型Redis**和**文档型MongoDB**，缺点就是没有事务处理，没有sql支持，结构相对复杂，不适合复杂查询。
4. 关系型数据库，表结构易于维护，sql语言通用，可以复杂操作；缺点就是读写性能差，表结构固定不太灵活，对于高并发的读写需求表现不好

# 二、MySQL
## MySQL基础
### 1. 连接查询
- 内连接和外连接的区别：主要在于如何处理不匹配的行
	- 内连接返回两个表中满足连接条件的匹配行（只包含两个表中所有对应记录的行）
	- 外连接
		- 左（外）连接：以左表为基准进行查询，坐标数据全部显示，右表如果和左表有匹配的数据则显示相应字段的数据，如果不匹配就显示NULL
		- 右（外）连接：以右表为基准进行查询，坐标数据全部显示，左表如果和右表有匹配的数据则显示相应字段的数据，如果不匹配就显示NULL
### 2. 聚合函数
- 概念：SQL中提供的聚合函数可以用来**统计，求和，求最值等**
- 分类：
	- count：统计行
	- sum：统计单个列的合计值
	- avg：计算平均值
	- max：算列最大值
	- min：算列最小值
### 3. SQL关键字
- 分页：limit
- 分组：group by
- 去重：distinct
### 4. 【三大范式】
- 第一范式：1NF **原子性**，列或字段不能再分，要求属性具有原子性，不可再分解
- 第二范式：2NF **唯一性**，一张表只能说一件事，是记录的唯一性约束，要求记录有唯一标识
- 第三范式：3NF **直接性**，数据不能存在传递关系，每个属性都和主键有直接关系，不是间接关系
### 5. MySQL数据如何存储在磁盘的（结合B+树）
- mysql中的每个数据库都存储为文件系统上的一个**目录**，每个表存储为一个**单独的文件**，mysql数据存放在磁盘中不是以行为单位的，而是**以数据页为单位的**，一页默认是16KB。存储多行数据，**数据之间通过单链表连接，页之间通过双向链表连接**（InnoDB）[^1][^2]
- 行溢出：一个页最多16KB = 16384字节，一行最多65535字节（因为有隐藏列，实际上是65532字节），大于16KB即为行溢出，触发**行溢出机制**[^3]
- 表的概念，逻辑上是表，物理上就是数据页16KB一页
### 6. 【DDL和DML区别】
- DML（Data Manipulation Language）：**数据操纵语言**。对数据库中的数据进行简单操作，比如insert、delete、update、select。**DML操作可以手动控制事务的开启、提交和回滚**。
- DDL（Data Definition Language）：**数据定义语言**。对数据库中的对象进行管理（database、table）。如create、alter、drop。**DDL操作时隐性提交的，不能rollback**。
- **主要区别**：DML是管理数据库中的数据，DDL是更改数据库的结构[^4]

### 8. MySQL关键字
#### - SELECT相关
- select：在表中查询数据
- from：指定查询的来源表
- where：过滤查询结果，保留满足条件的记录
- group by：按指定列对结果分组，常与聚合函数配合
- having：过滤group by分组后的结果（可用于聚合函数）
- order by：对查询结果排序（ASC升序，DESC降序）
- limit：限制返回结果的行数
- distinct：去除查询结果中的重复记录
#### - DML相关
- insert：向表中插入记录
- update：更新表中记录
- delete：删除表中记录
#### - DDL相关
- create：创建数据库、表、索引等对象
- alter：修改数据库对象（加列、修改字段类型）
- drop：删除数据库、表、索引等对象（不可逆）
- truncate：清空表中所有记录（保留表结构）
#### - JOIN相关
- join/inner join：内连接，只返回两表中匹配关联条件的记录
- left join/left outer join：左连接，返回左表所有记录，右表匹配失败为NULL
- right join/right outer join：右连接，返回右表所有记录，左表匹配失败为NULL
- on：指定表关联的条件
#### - 条件与逻辑运算
- and/or/not：逻辑运算符
- in：判断值是否在指定集合中
- not in：判断值不在指定集合中
- between and：判断值是否在指定范围内（包含边界）
- like：模糊匹配（ `%` 匹配任意字符，`_`匹配单个字符 ）
- is null / is not null：判断字段是否为NULL（不能用 `=` 或 `!=` 判断NULL）
#### - 聚合函数
- `count()`：统计记录数
- `sum()`：计算某列的总和
- `avg()`：计算某列的平均值
- `max() / min()`：获取某列的最大值 / 最小值
#### - 其他
- as：为列或表起别名
- union / union all：合并多个查询结果（union去重，union all保留所有）
- exists：判断子查询是否返回结果（存在则为true）
- primary key：定义主键（唯一的标识记录，**保证了数据的一致性**）
- index：创建索引（**提升了查询效率**）

## 事务
### 1. 事务四大特性ACID与实现原理
- 原子性Atomicity：事务是一个不可分割的工作单元，事务中的操作**要么全部发生，要么都不发生**。如果一部分成功，一部分失败，这时候就要回滚到事务开启前的状态
	- 实现：原子性依靠**undolog回滚日志实现**，每次对数据做修改或者删除插入的操作都会生成一条undolog来记录操作之前的数据状态，使用rollback的语句可以将所有执行成功的SQL语句产生的效果撤销。回滚日志先于数据持久化到磁盘上，回滚就是逆向操作。
- 一致性Consistency：**事务前后数据完整性一致**，数据的逻辑性一致（a给b转账，成功与否，俩人存款总额没变）
	- 实现：依靠其他三个性质实现，数据的完整性就是为了保证数据的有意义状态。
- 隔离性Isolation：数据库系统提供的隔离机制，**确保多个并发事务之间不会相互干扰，从而保证数据的一致性和准确性**。
	- 实现：通过**锁机制实现**，当事务操作数据的时候加锁，让事务执行前后看到的数据是一致的，并行执行事务和串行执行事务产生的效果一样。还可以利用MVCC实现快照读。
- 持久性Durability：一个事务一旦被提交，**他对数据库中的数据的改变就是永久性的**，即使数据库故障了也不会收到任何影响。
	- 实现：持久性通过**redolog重做日志实现**，redolog记录的是对数据库的操作。MySQL先把存放在硬盘上的数据加载到内存中，在内存中做修改再刷回磁盘，redolog使得在事务提交的时候将数据刷回磁盘。
