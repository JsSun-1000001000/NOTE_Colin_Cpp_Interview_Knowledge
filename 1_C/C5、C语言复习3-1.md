## 函数与指针

为什么使用指针？

因为代码不能一直在一个函数中写，要使用函数封装，让一个函数不能太长，但是有一些量需要跨函数，那么就需要使用地址间接使用变量，因而出现指针。

### 值传递 地址传递？

值传递，是实参给形参赋值，如`fun(int a = b);`，因而形参的值发生改变，并不能影响实参。
地址传递，是将地址的值从实参传给形参，形参有地址，可以间接访问空间并改写地址所指空间。

### 数据结构中，为什么数组传参要传长度？

`void fun(int arr[], int len);`

因为数组在传参的时候，传递的是指向数组首元素的指针

因为`sizeof(arr);`此时arr是一个指针，无法知道数组总空间的大小，那么就不直到数组多长，有越界的危险。因为字符串是以`\0`结束，即使不传长度也是可以的，不过要遍历一次得到长度，不如传参效率高。

`void fun(int arr[],int len);`等价于 `void fun(int *arr,int len);`

因为传入数组名，也是数组首地址，是一个地址，也就是指针

## 函数指针

写法：
`void fun(int a, int b);`fun替换为`(*pfun)`那么后面这个就是函数指针

## 什么是回调函数？

sort函数，epoll线程池中高效涉及到了回调

==一般的写法是函数的参数是一个函数指针，在函数中通过函数指针调用函数，还有一种写法，是将函数的指针提前登记，在需要时执行，比如线程池的写法==

```cpp
void sort(int arr[], int nlen, bool(*lpfun)(int a,int b)){
	if(lpfun(arr[0],arr[1])){
		swap(arr[0],arr[1]);
	}
}
```

## 调用约定

==约定参数怎么传递，谁来管理出栈，编译后名字的修饰方式==

常见的调用约定：`__cdecl__stdcall__fastcall`

|     调用约定     |  出栈方  |                       参数传递                       |                                名字修饰                                |
| :----------: | :---: | :----------------------------------------------: | :----------------------------------------------------------------: |
|  `__cdecl`   | 函数调用方 |                   从右至左的顺序压参数入栈                   |                            下划线+函数名（c编译）                            |
| `__stdcall`  | 函数本身  |                   从右至左的顺序压参数入栈                   | 下划线+函数名+@+参数的字节数，如函数`int func(int a,double b)`的修饰名是`_func@12`（c编译） |
| `__fastcall` | 函数本身  | 头两个DWORD（4字节）类型或占更少字节的参数被放入寄存器，其他剩下的参数按从右到左顺序压入栈 |                        @+函数名+@+参数的字节数（c编译）                         |

==**注意：scanf和printf函数内不知道使用空间的大小，只能调用者回收，即他们都是`__cdecl`；win32 api函数绝大部分都是`__stdcall`调用约定的。winapi其实也只是`__stdcall`的别名**==

## c++调用约定以及this指针

C++自己还有一种特殊的调用惯例，称为thiscall，专用于类成员函数的调用。

其特点随编译器的不同而不同，在vc里是this指针存放于ecx寄存器，参数从右到左压栈，而对于gcc，thiscall和cdecl完全一样，只是将this看作是函数的第一个参数。

C++和C编译是不一样的，一个是g++一个是gcc，所以修饰也是不一样的

|     调用约定     |          名字修饰          |
| :----------: | :--------------------: |
|  `__cdecl`   | ?+函数名@@YA+参数表@Z（C++编译） |
| `__stdcall`  | ？+函数名@@YG+参数表@Z（C++编译） |
| `__fastcall` | ？+函数名@@YI+参数表@Z（C++编译） |
参数表用代号表示：
X-void、D-char、E-unsigned char、F-short、H-int、I-unsigned int、J-long、K-unsigned long、M-float、N-double、\_N-bool

如：`?show@@YAXHD@Z`表示c++编译器调用约定`__cdecl`函数show返回值void，参数int char

==这就是，为什么c++有重载，c没有？==

==因为，sc编译完了函数名都一样的，c++编译完之后是不一样的==

==无法引用的外部符号错误：c++编译后的代码和c编译的不同所以无法引用==
解决办法：通过添加`extern "C"{}`，让这部分代码以C的方式编译

头文件里不能定义变量，加防止源文件重复包含也不行，只能extern（去链接一个外部变量/函数）

## extern的语法

- 多个源文件共享/链接全局变量或函数
```cpp
//a.c
int count = 0;
void foo(){cout<<foo()<<endl;}
//b.c
extern int count;//使用extern声明外部全局变量
extern void founction();//声明外部函数
```
- `extern "C" {}`：在C++中声明具有C语言编写的函数或变量的关键字。使用extern "C" 来告诉

## 字符串与指针

函数中定义，比较：
`char str1[] = "abcd";`第一个是==数组==，存在==栈区==
`char *str2 = "abcd";` 第二个是==变量==，存在==栈区==，==指向字符常量区==
总结如下：
1. str1数组名，是常量，不可改变，str2是指针变量，可以改变
2. str1是数组，存在栈区，str2是变量，存在栈区，指向字符常量区
3. `sizeof(str1)`数组所占空间，要把`\0`算在其中，值5；`sizeof(str2)`=指针大小=4
4. `str1[0] = 'x'`可以复制，`str2[0] = 'x'`不可以复制，因为在字符常量区，不可以改变，一般加const，比如`const char *str2 = "abcd";`。`strlen(str1)`不算`\0`结果是4；`strlen(str2)`结果是4

第二个问题：
```c
const char* buf1 = "abcdef";
const char* buf2 = "abcdef";
buf1 == buf2
```
结果为==**真**==！是同一个字符常量啊，在字符常量区

第三个问题：
```c
const char buf3[] = "abcdef";
buf1 == buf3;
```
结果为==**假**==！buf3在栈区！buf1在字符常量区，肯定不一样啊
