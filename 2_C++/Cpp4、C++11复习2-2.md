## C++四种类型转换

**C语言里有强制类型转换，为什么不继续沿用，而存在这四种类型转换？**
- C++在设计时，强调类型安全，但是C中的类型转换无所不能，沿用的话，会破坏C++的类型系统，还会留下安全隐患
- 此外，四种类型转换还有他们使用的不同场景和功能，组合使用较C中的强制类型转换更强大
### static_cast <类型>(待转换量)

- 编译时确定的，相关内容的转换，数与数之间 int short char 之间 int \* 与 void \* 之间
- 继承中对象的向上和向下转换可以（向下转换，没有检查，可能会有问题）
- （注：A是B的父类，B->A 继承中对象的向上转换， A->B 向下转换）
父类指针指向子类对象——子类向父类转换
```cpp
	A * pa = new B;//子类一般比父类空间大，转换了不存在安全问题
	B * pb = (B*) new A;//父类向子类转换（向下转换） 会报错不强转是不通过的
```
- 不相关的不能转换，student \* 与 int \*不能，char \* 与 int \* 之间也不能（因为不安全），int->int \* 不可以，int \*->int也不可以
- `(type)`强制类型转换，支持的类型更多，强转可以

例：
父类A 子类 A1(fun1) A2(fun2) A3(fun3) 
`A * pa = new A1;`
//向下
`A2 * pa2 = static_cast<A2*>(pa);//转换可以 但是后面可能会出问题`
`pa2->fun2();`
### dynamic_cast <类型>(待转换量)

- 只适用于继承上两个类之间的转换
- 继承的向上转换等同于`static_cast`
- ==**继承的向下转换，会进行检验**==
- 非多态的对象不能用

**dynamic_cast 怎么检验？**
- 向下转换安全（即父类指针要转换为子类指针，恰巧这个父类指针指向这个子类对象）可以得到对应结果
- 向下转换不安全（即父类指针要转换为子类指针，恰巧这个父类指针不指向子类对象），返回结果为空
- ==**向下转换，父类中必须包含虚函数——会把类型写入虚表**==（`static_cast`没有这个要求）

**特殊情况：**
- 向下转换安全（即父类指针要转换为子类指针，恰巧这个父类指针指向这个子类的子类对象——爷爷指向孙子，要转成父亲）
```cpp
A * pa = new C;
dynamic_cast<B*>(pa);
```

**static_cast 与 dynamic_cast 区别总结：**
- `static_cast`支持相关数据类型转换，`dynamic_cast`不支持
- 对于继承关系中的转换，`static_cast`可以向上和向下转换，`dynamic_cast`向上转换与`static_cast`一致，向下转换，父类要有虚函数，并且存在检验机制
- `static_cast`不支持交叉转换，只能是向上下，`dynamic_cast`可以交叉转换（左子树的往右子树转）

**为什么用dynamic_cast？**
- 父类指针指向子类对象，可以正确的调用子类的特有方法
```cpp
F * pF = new S1;
void play(F * pF){
	S2 * s2 = dynamic_cast<S2*>(pF);
	if(s2)
		s2->fun2();
}
```

### const_cast <类型>(待转换量)

去常转换`int * p = const_cast<int*>(const_int_lp);`
- const->非const，不能改变基础类型
- volatile->非volatile

**作用：**
- 可以修改，尤其是`const A* -> A*`或者`const A -> A`
- 常对象只能调用常函数，并且对象的属性不能修改，去常转换后，可以调用任何类成员函数，并且可以修改属性值

**volatile**
- 防止修饰变量编译优化
- 避免修饰变量缓存和内存不一致（每次到其地址读取，先写后读）
- 程序员小灰里面会讲（怎么都是java的东西`(＠_＠;)`）

### reinterpret_cast <类型>(待转换量)

重解释类型转换

- 是C++里的强制类型转换
- 相当于`(type)`，无所不能
- 有安全隐患，一般编译的时候不过度使用
