## 单例模式

**为什么选择？**
1. 避免重复
2. 该类只需要一个对象，并提供了一个全局访问点来获取实例。控制对象的创建过程，避免资源重复占用或状态不一致
3. 用在数据库连接池，日志管理，配置信息，线程池，缓存系统等

**核心原则？**
- 私有化构造函数：禁止外部通过new创建实例 
- 自行创建实例：类内部负责创建唯一实例
- 全局访问点：通过静态方法`getInstance()`提供实例访问

**如何实现？**
1. 构造析构拷贝构造私有
2. 提供静态公有的获取对象的方法

==C++11部分==

**例子：**
```cpp
class SingleTon{
public:
	static SingleTon* GetInstance(){
		static SingleTon s;
		return &s;
	}
private:
	SingleTon(){}
	~SingleTon(){}
	SingleTon(const SingleTon & s){}
}
```

**优点：**
- 全局访问点，提供了一个全局访问点，使得系统中任何地方都可以访问该实例
- 节省资源，由于只创建了一个实例，减少了系统资源开销，适用于频繁创建和销毁对象的场景
- 严格控制实例化，单例类自己控制实例化过程，可避免其他类意外创建多个实例
**缺点：**
- 全局状态风险，单例可能被滥用为全局变量，导致代码高耦合
- 多线程问题，若未正确实现线程安全，在多线程环境下可能创建多个实例
- 扩展性受限，单例类的扩展困难，因为继承和多态难以应用于单例模式
- 可能导致内存泄漏，单例对象通常在程序整个生命周期存在，若持有资源（文件句柄、网络连接）未正确释放，可能导致内存泄漏

## 工厂方法模式

![[工厂方法模式.png]]
- **简单工厂模式**：通过一个工厂类来创建不同的产品对象，适用于产品种类较少且不需要扩展的场景。它不支持增加新产品。
- **工厂方法模式**：通过定义一个创建对象的接口，由多个具体工厂类来实现，适用于需要扩展新产品的场景。它支持增加新产品，但每个工厂只负责创建一种产品。

**为什么用工厂，不直接new？**
- 因为我们可以不需要直到子类，不然在使用时，需要子类类名

**简单工厂&工厂方法模式**
- 简单工厂在我们使用的时候，去除了对类名的依赖，比如只需要+-就可以创造类
- 不过由于如果需要添加新的计算，需要加新的判断，改代码破坏开闭原则
- 工厂方法模式，需要什么运算，创建什么工厂，并创建对应的运算类

## 抽象工厂模式

提供一个创建一系列相关或相互依赖对象的接口，而无需指定他们具体的类。大工厂套小工厂

例子：
- 假如你的项目原来的数据库方案是mysql，后来用access，那么适合在最初设计使用抽象工厂
![[抽象工厂模式.png]]
**优点：**
- 客户不需要知道类型，通过工厂可以切换创建的对象
**缺点：**
- 如果创建的对象多加一类，会导致工厂类修改
- 比如上面例子中，再添加项目表project，那么需要改变抽象工厂，mysql工厂和access工厂，添加CreateProject

**和其他工厂区别：**
- 抽象工厂是一个工厂，可以生产一系列相关或相互依赖的对象的创建，类似创建大类型
- 简单工厂是类似创建小类型
- 可以使用多个简单工厂改进抽象工厂

## 中介者模式

- 用一个中介对象封装一系列的对象交互（网状结构改为星状结构，中介者类是中间的桥）
- 中介者使用各对象不需要显示地相互引用，从而使其耦合松散，而且可以独立地改变他们之间的交互

中介二字：
网络和核心类之间的交互，通过网络中介进行交互

![[终结者模式类图.png]]

**优点：**
- <span style="background:#affad1">降低耦合度，对象只需要依赖中介者，而非直接相互依赖</span>。这使得系统更易于维护和扩展
- <span style="background:#affad1">集中控制交互逻辑</span>，对象间的交互逻辑被集中在中介者中，便于统一管理和修改
- 符合开闭原则，新增具体同事类或中介者类时，<span style="background:#affad1">通常不需要修改现有代码，只需要扩展即可。</span>
- 简化对象协议，对象之间的通信被简化为中介者的通信，<span style="background:#affad1">减少了信息传递的复杂性</span>
**缺点：**
- <span style="background:#affad1">中介者可能过于复杂</span>，当系统中的交互逻辑较多时，中介者会变得庞大复杂，
- 降低对象可复用性，<span style="background:#affad1">对象的行为依赖中介者</span>，导致调试时难以定位问题
- 调试难度增加，中介者集中了大量逻辑，可能导致调试时候难以定位问题。
- 可能导致性能问题，所有交互都通过中介者进行，可能在<span style="background:#affad1">高并发场景下成为性能瓶颈</span>
