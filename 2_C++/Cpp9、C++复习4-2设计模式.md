## 单例模式

**为什么选择？**
1. 避免重复
2. 该类只需要一个对象，并提供了一个全局访问点来获取实例。控制对象的创建过程，避免资源重复占用或状态不一致
3. 用在数据库连接池，日志管理，配置信息，线程池，缓存系统等

**核心原则？**
- 私有化构造函数：禁止外部通过new创建实例 
- 自行创建实例：类内部负责创建唯一实例
- 全局访问点：通过静态方法`getInstance()`提供实例访问

**如何实现？**
1. 构造析构拷贝构造私有
2. 提供静态公有的获取对象的方法

==C++11部分==

**例子：**
```cpp
class SingleTon{
public:
	static SingleTon* GetInstance(){
		static SingleTon s;
		return &s;
	}
private:
	SingleTon(){}
	~SingleTon(){}
	SingleTon(const SingleTon & s){}
}
```

**优点：**
- 全局访问点，提供了一个全局访问点，使得系统中任何地方都可以访问该实例
- 节省资源，由于只创建了一个实例，减少了系统资源开销，适用于频繁创建和销毁对象的场景
- 严格控制实例化，单例类自己控制实例化过程，可避免其他类意外创建多个实例
**缺点：**
- 全局状态风险，单例可能被滥用为全局变量，导致代码高耦合
- 多线程问题，若未正确实现线程安全，在多线程环境下可能创建多个实例
- 扩展性受限，单例类的扩展困难，因为继承和多态难以应用于单例模式
- 可能导致内存泄漏，单例对象通常在程序整个生命周期存在，若持有资源（文件句柄、网络连接）未正确释放，可能导致内存泄漏
