
RAII思想——Resource Acquisition Is Initialization

智能指针——万能皆可对象，指针封装->类 构造 析构->回收指针所指向的空间 自动回收空间

==**四个智能指针：`auto_ptr; unique_ptr; shared_ptr; weak_ptr`**==

其中`auto_ptr`已经弃用了
### 四个指针
- `auto_ptr`采用所有权模式
- `unique_ptr`独占式指针，同一时刻只能有一个指针指向同一个对象
- `shared_ptr`共享式指针，同一个指针可以有多个指针指向同一个对象
- `weak_ptr`用来解决`shared_ptr`相互引用导致的死锁问题
### auto_ptr
- C++11已弃用，`auto_ptr`对象过期时，析构函数会自动delete释放所指向的内存。
- 缺陷1：在复制和拷贝时会发生所有权转移，原指针变成空指针。这容易导致未定义的行为，不好调试；
- 缺陷2：不支持数组的管理，只有`delete`没有`delete[]`，内存释放会出问题
- 缺陷3：不符合STL容器对于元素拷贝语义的要求，在STL里用不了
### unique_ptr
- 独占式的概念，保证同一时间只有一个智能指针可以指向该对象，避免了内存泄漏
- 不允许拷贝和赋值，确保资源独占性
- 支持管理数组了，还能作为函数返回值
### shared_ptr
- 共享式概念，允许多个智能指针指向相同的对象，通过引用计数来管理对象的声明周期，引用计数减到0会被自动释放
- 但是在多线程环境中使用要注意线程安全问题（因为引用计数的修改不是原子操作，可能导致数据竞争），用的时候可以加互斥锁
### weak_ptr

## auto_ptr

小例子：
```cpp
#include <iostream>
#include <vector>
#include <string>
#include <memory>

using namespace std;

class A{
public:
	AAAA(const string str){
		s=str;
		cout<<"AAAA:"<<s<<endl;
	}	
	~AAAA(){
		cout<<"~AAAA"<<endl;
	}
	void say(){
		cout<<"Say:"<<s<<endl;
	}
private:
	string s;
};

```
### auto_ptr 创建对象
```cpp
auto_ptr<AAAA> ap1(new AAAA("auto-ptr"));
auto_ptr<AAAA> ap2;
ap2.reset(new AAAA("auto_ptr2"));
auto_ptr<AAAA> ap3;
ap3 = ap1;
```
### auto_ptr使用对象
```cpp
ap3.get()->say();
ap3->say();
```
### auto_ptr主动回收对象
```cpp
ap3.reset();//析构
ap3.release();
```
### auto_ptr存在的问题

使用交出的太随意了，交出后，原指针为空，会失效，再调用会出问题
```cpp
ap1->say();
//ap1析构不会有问题
```
## unique_ptr——唯一所有权智能指针

### 创建方式——相同
```cpp
unique_ptr<AAAA> up1(new AAAA("unique_ptr"));
unique_ptr<AAAA> up2;
up2.reset(new AAAA("unique_ptr2"));
```
### 使用权传递
```cpp
unique_ptr<AAAA> up3;
up3 = std::move(up1);//避免重复资源
```

**C++11 unique_ptr 用于替代废弃的 auto_ptr， 使用权传递的方式要求更严格，不可以直接赋值**

## shared_ptr 共享所有权智能指针

类似于文件系统的 引用计数

- 多个指针指向同一个堆空间，通过引用计数（use_counts），来记录所有权的指针个数
- 当引用计数为0时，回收这个堆空间
### 定义对象
```cpp
shared_ptr<AAAA> sp1(new AAAA("shared_ptr1"));
shared_ptr<AAAA> sp1 = shared_ptr<AAAA> (new AAAA("shared_ptr1"));

shared_ptr<AAAA> sp2;
sp2.reset(new AAAA("shared_ptr2"));

shared_ptr<AAAA> sp3;
sp3 = make_shared<AAAA>("shared_ptr3");
{
	shared_ptr<AAAA> sp4;
	sp4 = sp3;//指向同一个 共享
	cout<<sp4.use_count()<<endl;
}
//使用sp3.get()->say(); sp3->say();
sp3.use_count()//查看引用计数 主动挥手空间sp3.reset()
```
## weak_ptr 
### shared_ptr 的问题
```cpp
class CCC;
class BBB{
public: 
	BBB(){
		cout<<"BBB"<<endl;
	}
	~BBB(){
		cout<<"~BBB"<<endl;
	}
	shared_ptr<CCC> spc;
};
class CCC{
public:
	CCC(){
		cout<<"CCC"<<endl;
	}
	~CCC(){
		cout<<"~CCC"<<endl;
	}
	shared_ptr<BBB> spb;
	//weak_ptr<BBB> spb;
};
{
	shared_ptr<BBB> pb(new BBB());
	shared_ptr<CCC> pc(new CCC());
	pb->spc = pc;
	pc->spb = pb;
}
```

sp指向捆绑结构，捆绑结构内一个指针指向新申请的堆区空间，另一个是引用计数器；weakptr有sp引用计数和wp引用计数
## weak_ptr 

- weak_ptr 是 ==弱引用计数的共享使用权的智能指针==
- weak_ptr 指向同一空间（==通过shared_ptr指向，weak_ptr自身并不能指向空间==）
- 引用计数==不会加一==
- 他的提出==主要是解决shared_ptr存在循环引用的问题==

### shared_ptr注意事项

- 避免循环引用
- 多线程环境注意线程安全
### weak_ptr注意事项

- 避免悬空指针，使用weak_ptr之前，必须确保其所指向的对象仍然存在
- weak_ptr应该通过shared_ptr构造而来，不可以直接从裸露指针构造
- 注意失效 当最后一个shared_ptr所引用的对象被释放时，weak_ptr会自动失效
- 多线程环境注意线程安全
