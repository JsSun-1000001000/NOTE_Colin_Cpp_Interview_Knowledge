## 设计原则SOLID CD

1. ==单一==原则（**Single Resposibility Principle**）：功能单一，方便组合和服用
2. ==开闭==原则（**Open Close Principle**）：对扩展开放，对修改关闭
3. ==里氏代换==原则（**Liskov Substitution Principle**）：任何基类可能出现的地方，子类一定可以出现
4. ==依赖倒转==原则（**Dependence Inversion Principle**）：针对接口编程，依赖于抽象而不依赖具体
5. ==接口隔离==原则（**Interface Segregation Principle**）：使用多个隔离的接口，比使用单个接口更好
6. ==迪米特==原则—最少知道原则（**Law of Demeter**）：一个实体应当尽量少和其他实体之间发生的相互作用，使得系统功能模块相对独立（==拿例子说==，耦合小，复用强）（==信号和槽的实现==）（==生产者消费者模型==）
7. ==合成复用==原则（**Composite Reuse Principle**）：尽量使用合成/聚合的方式，而不是使用继承

### 1、单一职责

函数里的功能尽量拆开，这样可以随便组和不受限制

## 2、开闭原则

可以通过子类继承，然后子类重写，这样避免修改父类的实现

【父类（功能A）】——修改功能A——>【子类（重写功能A）】

例子：
- ==QT自定义控件==，创建maindialog，继承自QDialog，上来就重写了hhh

## 3、里氏代换——儿子替换父亲

做的事是接口统一：
```cpp
A * GetInstance(int type){
	switch(type){
		case type_A1:return new A1;
		break;
		case type_A2:return new A2;
		break;
	}
	return nullptr;
}
```
上面例子中，如果想用子类对应的方法，要如何实现？动态转换（dynamic_cast）

> [!NOTE] 子类和父类之间的类型转换？
> 隐式类型转换、静态类型转换`static_cast`、重新解释类型转换`reinterpret_cast`、动态类型转换`dynamic_cast`

## 4、依赖倒转原则——面向接口编程

到底在哪修改？接口是不能改的
![[依赖倒转原则.png]]
例子：
- 网络，写一个接口，核心类调用接口完成网络的各种功能，一旦写好，不会再改变，需要改变，只需要改子类的实现。
## 5、接口隔离原则——使用多个隔离接口

![[接口隔离原则.png]]
例子：
- 订单系统，订单类，分为三个方面：门店订单OrgerForSeller、用户订单OrderForBuyer、管理者订单OrderForAdmin
- <span style="background:#affad1">订单类多继承上面的接口，然后实现接口方法。应用中，接口指针指向订单对象，从而完成接口隔离</span>
- 降低耦合
## 6、迪米特原则——降低耦合增强复用

![[迪米特原则.png]]
例子：
- 有三个类：总公司类、分公司类、分公司员工
- 总公司想打印分公司员工名单，直接调用分公司的员工的名单函数
- 飞机大战为什么写管理类？炮弹盒子（链表里放炮弹）只需要调用盒子

**什么是低耦合，高内聚？**
- 降低彼此的羁绊（依赖少），职责尽量单一（纯净）
## 7、合成复用原则——尽量使用组合关联等关系，代替继承

![[合成复用原则.png]]
例子：
- 服务器有数据库查询的方法，服务器写一个接口，~~实现用子类来实现~~（不要这么写，换数据库了子类重写父类方法，服务器也要改）
- 不用继承的方式，但是保留多态，数据库的东西单独拿出去
