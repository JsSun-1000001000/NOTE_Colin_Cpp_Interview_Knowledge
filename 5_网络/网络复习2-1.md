## TCP流量控制——滑动窗口

- 窗口概念：TCP是==每发送一个数据，都要进行一次确认应答==。当上一个数据包收到了应答了，再发送下一个。这个模式就有点像面对面聊天，你一句我一句。缺点是效率低（一句一句->互发小作文？）
- 有了窗口，就可以指定窗口大小，窗口大小就是无需等待确认应答，而可以继续发送数据的最大值
- 窗口大小由哪一方决定？三次握手的时候，会交换窗口的大小，==通常窗口的大小是由接收方的窗口大小来决定的==。发送方发送的数据大小，不能超过接收方的窗口大小，否则接收方就无法正常接收数据

## 粘包问题解决

### 什么时候发生？

- TCP是数据流传输，是一种没有边界的，可以合并的传输数据方式
- 合并就要能拆开，拆不开就是粘包
- 解决办法：==1、先发数据长度，再发包大小（不要分两次写，容易乱）；2、固定包大小（游戏）；3、标志位；4、短连接（监控）==
例子：
```cpp
struct Node n1;
int nSize = sizeof(n1);
send(sockClient,(char *)&nSize,sizeof(int),0);
send(sockClient,(char *)&n1,sizeof(n1),0);

int nPackSize = 0;
recv(sockClient,&nPackSize,sizeof(int),0);
char * buf = new char[nPackSize];
recv(sockClient, buf, nPackSize,0);//再收数据包
delete[] buf;
```
（传文件、音视频等数据量大的情况，比如recv 给了默认len）
### Nagle算法与TCP_NODELAY（'nagle——( ⓛ ω ⓛ \*)）

- 使用Nagle算法，算法的思路是延时处理，满足以下两个条件中的一条才可以发送数据：
	- 没有==已发送未确认==报文时，立刻发送数据
	- 存在未确认报文时，直到==没有已发送未确认报文==或==数据长度达到MSS大小==时，再发送数据
- Nagle算法默认是打开的，如果对于一些需要小数据包交互的场景的程序，比如，telnet或ssh这样的交互性比较强的程序，则需要关闭Nagle算法
- `setsockopt(sock_fd,IPPROTO_TCP,TCP_NODELAY,(char *)&value,sizeof(int));`
