- 硬链接和软链接区别
	- 分别是什么
	- 区别
		- 指向
		- 跨文件系统
		- 链接目录
		- 删除原始文件

- 软链接：指向文件路径；可以跨文件系统；可以链接目录；删除原始文件会导致软链接失效（“悬空链接”）

### 12. Linux启动流程（BIOS、MBR、GRUB、内核加载、init进程）？

笔记：
1. 开机后，BIOS进行自检，保证硬件能够正常工作，然后根据系统设置的启动顺序查找硬盘，找到MBR主引导记录
2. MBR主引导记录一般在硬盘第一个扇区，包含了引导加载程序的代码和分区表。大小512字节，系统将MBR加载到内存后开始执行，此时，引导加载程序的第一阶段开始
3. GRUB两个阶段：一阶段从MBR加载到内存中；二阶段根据配置文件加载Linux内核和必要的驱动程序，并将控制权交给内核
4. 内核加载后，系统会初始化硬件设备，加载驱动程序，挂载根文件系统。内核会用只读的方式挂载根文件系统，并开始执行初始化过程。此时内核会调用`start_kernel()`函数，启动一系列初始化函数，完成核心环境建立
5. 内核加载成功后，第一个运行的用户空间进程是`/sbin/init`。`init`负责启动系统服务和用户会话
### 13. 进程和线程的区别？

思路：
[list2pumlMindmap]
- 进程和线程的区别
	- 基本单位/容器与执行单元
	- 代码/地址/数据空间
	- 进程与线程关系
	- 崩溃后产生的影响
	- 程序运行出入口/执行序列
笔记：
- 进程是操作系统资源分配的基本单位，线程是任务调度和执行的基本单位；进程是容器；线程是执行单元
- 每个进程有独立的代码和数据空间，切换开销大；同一类线程共享代码和数据空间，有独立的执行栈和pc，切换开销小
- 线程是进程一部分
- 同一进程的线程共享进程的地址空间和资源，进程之间空间和资源是独立的
- 进程崩溃后，不会对其他进程产生影响；但是一个线程崩溃整个进程都崩溃；多进程比多线程要健壮
- 每个独立的进程有程序运行的入口、顺序执行序列和程序出口；但是线程不能独立执行，必须依存在应用程序中，由应用程序提供多个线程执行控制，两者均可并发执行
- linux下线程是轻量级进程，lpthread

### 14. 线程是如何实现同步的？ 

思路：
[list2pumlMindmap]
- 常用的线程同步机制
	- 互斥锁mutex
	- 信号量semaphore
	- 条件变量condition variable
	- 读写锁read-write lock
	- 原子操作
	- **屏障barrier**

笔记：
1. 互斥锁mutex：可以保证在==**同一时间只有一个线程可以访问共享资源**==。当一个线程获得了互斥锁后，其他线程需要等待该线程释放锁才能继续访问共享资源。
2. 信号量semaphore：是一种==**计数器，用来控制同时访问某个共享资源的线程数量**==。当计数器大于0时，线程可以访问资源并将计数器减1；当计数器等于0时，线程需要等待其他线程释放资源后才能继续访问。
3. 条件变量condition variable：==**用于线程之间的通信和协调**==。一个线程可以等待某个条件的发生，而另一个线程可以在满足条件时通知等待的线程继续执行。
4. 读写锁read-write lock：==**允许多个线程同时读取共享资源，但只允许一个线程写入共享资源**==。这样可以提高读取操作的并发性，同时保证写入操作的原子性。
5. 原子操作：原子操作是一种不可中断的操作，要么全部执行成功，要么全部不执行。==**原子操作可以保证多个线程同时访问共享资源时的数据一致性**==。
6. **屏障barrier**：用于线程之间的同步，**==屏障允许每个线程在某个点上等待，直到所有线程都到达这个点后再继续执行。==**
### 15. 页面置换算法？ OPT、LRU、LFU、FIFO

思路：
[list2pumlMindmap]
- 页面置换算法(从夯到拉，并不绝对)
	- OPT——不可实现的概念神
	- ARC——综合最强，结合了LRU LFU
	- 改进型CLOCK——LRU的变体
	- LRU——利用了时间局部性原理
	- LFU——利用了访问频率，无法适应访问模式的变化
	- CLOCK——LRU的廉价版
	- NRU——CLOCK粗糙版本
	- FIFO——最简单的队列管理，可能导致Belady异常
	- MFU——只有频繁访问新数据的时候有用，其他情况命中率极低

笔记：
1. **OPT（Optimal）**：优先淘汰最长时间内不会被访问的页面。缺页率最小，性能最好，但无法实现
2. **ARC（Adaptive Replacement Cache）**
3. **改进型CLOCK**：在CLOCK基础上增加了==**访问位，修改位**==，在其他条件相同时==**优先淘汰没有修改过的页面**==。开销较小，性能也不错，Linux采用的是改进型CLOCK的变种。
4. **LRU（Least Recently used）**：最近最少使用，每次淘汰的页面是最近最久未使用的页面，赋予每个页面对应的页表项中，用访问字段记录该页面自上次被访问以来所经历的时间t。但需要专门硬件支持，开销较大。
	- LRU的实现：数组、链表、哈希+链表
5. **LFU（Least Frequently Used）**：最近最少未被使用（LFU看的是访问频率，LRU看的是访问时间）
	- LFU的实现：`unordered_map`+数组、`unordered_map`+小顶堆、二级哈希映射（Java里是hashmap，对应C++的`unordered_map`）
6. **CLOCK（NRU）**：最近未用。为每个页面设置一个访问位，再将内存中的页面都通过链接指针链接成一个循环队列。当某页被访问时，其访问位置为1。当需要淘汰一个页面时，只需检查页的访问位。如果是0，就选择该页换出；如果是1，则将它置为0，暂不换出，继续检查下一个页面，若第一轮扫描中所有页面都是1，则将这些页面的访问位依次置为0后，再进行第二轮捆描（第二轮扫描中一定会有访问位为0的页面，因此简单的CLOCK算法选择一个淘汰页面最多会经过两轮扫描)
7. **NRU**：其实差不多，可以当一个看，也有说是更粗糙的版本
8. **FIFO**：优先淘汰最先进入内存的页面，实现简单，性能不行，**==可能会出现Beady异常==**
9. **MFU**：有先替换最频繁访问的页面（MFU认为，最频繁访问的页面未来不再需要。。。），在大多数情况下，表现都不好，命中率极低。但也有用武之地，比如页面访问次数严格递减。一般MFU和LFU都是不经常用的。

### 16. 虚拟内存、物理内存
#### a、了解虚拟技术吗？

思路：

笔记：
- 虚拟技术是把一个物理实体转换为多个逻辑实体
- 主要有两种虚拟技术：==**时分复用、空分复用**==
- ==多进程和多线程==使用了时分复用，多个进程在同一处理器上并发执行，让每个进程轮流占用处理器，每次只执行一个小时间片并快速切换
- ==虚拟内存==使用了空分复用，通过把物理内存抽象为地址空间，每个进程都有各自的地址空间，然后地址空间的页会被映射到物理内存，，地址空间的页不需要全部放在物理内存中，当用到没在物理内存的页时，执行页面置换算法，把页换到内存中。

#### c、内存管理机制

思路：

笔记：
- 内存的管理就是通过内存交换技术，把不常用的部分放到硬盘，需要的时候在换回来
- 这种管理需要虚拟地址和物理地址之间的映射，映射的方式有三种：分页、分段、段页式
- **分段**：分段式根据程序的逻辑来分出栈段、堆段、数据段、代码段。段是一块连续的空间，但是大小不是统一的，可能会导致==内存碎片==和==内存交换效率低==的问题
- **分页**：分页是把虚拟空间和物理空间分成固定大小的页（Linux中每一页是4KB）解决了分段大小不统一导致的内存碎片问题，也能提高交换效率
- **多级页表**：解决分页产生的页表过大问题，就有了多级页表，多级页表会导致cpu寻址时间开销增加，就有了TLB快表
- **段页式**：兼具两者优点，但软硬件需求增加，提升了系统复杂性和开销。段页式存储管理将用户程序先分成若干段，每段再分成若干页。逻辑地址由段号、段内页号和页内地址三部分组成。段表记录每段的页表基址和长度，页表记录每页的物理地址。
#### d、什么是TLB快表

思路：

笔记：
- TLB是联想寄存器，访问速度比内存块的高速缓存，存放当前访问的若干页表项，用来加速地址变换的过程。TLB是快表，内存里的就是慢表
- 解决多级页表带来的时间开销问题
#### e、有无快表的区别

思路：

笔记：
- 有快表：算页号，页内偏移量——检查页号合法性——查快表——命中直接读取对应的内存块号，用页内偏移量找物理地址——未命中就查页表，找到后把页表存到快表里——根据对应的内存块号和页内偏移量找物理地址（命中只需要一次访存）
- 没有快表：就没有查快表的操作，其他都一样（两次访存）
#### f、有快表的地址转换过程

思路：

笔记：
- cpu给出逻辑地址，硬件算出页号、页内偏移量，然后页号和TLB里的页号比较
- 如果有匹配的，说明命中了，直接拿对应的内存块号，和偏移量拼成物理地址，访问内存单元
- 如果没有匹配，就要访问内存中的页表，找页表项，得到页面存放的内存块号，最后拼出物理地址，同时把这个页表项存到TLB中
- TLB满了会有置换算法的，而且TLB一般命中率可以到90%

### 17. 零拷贝的方式

sendfile + DMA 真正意味上的零拷贝==**（1、2是主要的一定要答）**==

1. **sendfile**： sendfile 是一种系统调用，允许直接将文件数据从内核缓冲区传输到网络套接字，避免了用户态和内核态之间的额外拷贝。它依赖 DMA 技术和文件描述符传递。
2. **mmap + write**： mmap 将文件映射到用户空间，使用户程序可以直接访问文件内容。通过共享内核缓冲区和用户缓冲区，减少了一次数据拷贝。+write
3. **Direct I/O**： Direct I/O 绕过了内核缓冲区，直接在用户空间和磁盘之间传输数据。这种方式完全避免了内核态的拷贝，但需要硬件支持。
4. **splice**： splice 允许在两个文件描述符之间直接传输数据（如管道和套接字），无需经过用户空间，从而减少了数据拷贝次数。Linux 内核在 2.6 版本引入。

### 23. 信号量和条件变量的区别

思路：

笔记：
- **功能上**：
	- 条件变量：用于在线程之间等待某个条件满足的情况下才进行操作。

- **用途**：
	- 条件变量通常在多个线程之间等待某个条件满足的情况，和互斥锁一起用，避免竞态条件
	- 信号量适用于对共享资源的访问进行限制，可以用于实现互斥锁和线程同步

### 26. [[高频]] select、poll、epoll的区别？为什么epoll效率更高？

思路：
[list2pumlMindmap]
- select/poll/epoll的区别
	- IO效率
		- 靠什么驱动
		- 时间复杂度
	- 操作方式
		- 遍历方式
	- 底层实现
		- select底层
		- poll底层
		- epoll底层
	- 最大连接数
		- select
		- poll和epoll
	- 对描述符的拷贝
		- select和poll
		- epoll
	- 性能
		- 高并发情况下
		- 连接数少且十分活跃情况下
	- 平台支持
		- select
		- poll
		- epoll
笔记：
- IO效率：select和poll需要无差别轮询所有的描述符集合，时间复杂度为$O(n)$；epoll是事件驱动的，当描述符就绪时，回调函数会把描述符放到就绪队列里面，时间复杂度为$O(1)$
- 操作方式：select和poll采用遍历，而epoll采用了回调
- 底层实现：select底层是数组；poll底层是链表；epoll底层是红黑树
- 最大连接数：select最大连接数为1024或2048；poll和epoll无上限（受限于系统）
- 对描述符的拷贝：select和poll每次调用都会把描述符集合从用户态拷贝到内核态；epoll在调用`epoll_ctl`时会拷贝进内核并保存，之后每次`epoll_wait`时不会再拷贝
- 性能：epoll在高并发的情况下性能远超select和poll；但在连接数少且都十分活跃的情况下，select和poll性能比epoll好（因为要很多函数回调）
- 平台支持：select在Windows、Mac、Linux上都支持；poll是类unix系统都支持；epoll是Linux独有的
